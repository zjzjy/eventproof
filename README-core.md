# 事证 Core · 最核心的一条链路

> 从“关注标的”开始，到自动生成事件、逐步同步新证据、通知、版本演化的一条完整演示链路。没有规则演练入口，也没有 scenario 参数。

## 打开

公网正式入口：

**https://zjzjy.github.io/eventproof/core-simple.html**

首次进入先关注 `002792 通宇通讯`；关注后事件进入抽屉，再用“同步最新”逐步接收传闻、否认、市场反应和签署协议。

## 关注入口与多事件抽屉

页面标题下方有一个轻量的“关注事件”抽屉：

- **002792 通宇通讯收购佳贤通信**：自动进入，来源徽标“自动 · 关注标的”。
- **300209 行云科技算力卡海关传闻**：点击打开第二个真实事件的精简详情；3 个节点，来源链接到 CNINFO。
- **“＋ 关注标的”**：输入代码后写入静态演示关注列表；提示实时抓取需要后端连接器。
- **“关注事件 / 已关注事件”**：切换当前事件关注状态，状态存 `localStorage`。

这不是账号系统：GitHub Pages 版本只把关注状态保存在当前浏览器；后端版对应 `watchlist_items` 和 `event_follows`。

如果后端已在运行：

**http://127.0.0.1:8000/core.html**

如果没在运行：

```powershell
cd apps\api
..\..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

## 完整演示流程

1. **首次进入**：页面只显示“先关注一个标的”，输入 `002792` 并点关注。
2. **系统处理**：显示“抓取公告 → 抽取 claim → 归并事件”，生成 v1。
3. **事件进入抽屉**：来源徽标为“自动 · 关注标的 002792”；当前结论只包含 08-05 公告事实、观点和预测。
4. **同步最新**：
   - 第一次：08-07 传闻 → v2“传闻待核实”；
   - 第二次：08-07 官方否认 → v3“传闻已否认”，通知 1 条 P0；
   - 第三次：08-08 市场异动 → v4“市场已反应”，通知累计 2 条；
   - 第四次：09-22 签署协议 → linked Event，通知累计 3 条。
5. **查看通知/关注事件**：点顶部“通知 N”跳到最新变化；可关注/取消关注当前事件。
6. **多事件**：在“＋ 关注标的”输入 `300209`，行云科技事件进入抽屉；点击可看第二个真实事件。

页面所有同步动作都是演示快照，不是实时抓取；版式保持“当前结论 → 时间口径 → 演化节点 → 结论变化 → 核对项 → 判断口径”。

页面顶部先给“最关键的三件事”：真的（3亿元/25%/不并表）、被否认/容易误读（英伟达合作/2000亿市场/开源生态不等于合作）、需要重新评估（澄清前两次三日涨超20%）；演化表之后是“还需要核对”（估值、25%经营影响力、传闻原始来源）。

## 证据等级

| 等级 | 含义 | 怎么用 |
| --- | --- | --- |
| A | 官方原文 | 交易所/公司公告，可直接作为事实 |
| B | 有原文的转述 | 正规媒体引用官方，需核对原文 |
| C | 无原文转述 | 网络传闻/匿名消息，只能当线索 |
| D | 已否认/撤回 | 不作为事实，保留在版本记录里 |

本页的判断逻辑只有三条：**来源是不是官方、有没有原文、有没有独立佐证**。不再展示六根柱状图。

注意：A/B/C/D 是**来源等级**，不是主张类型。A 级来源里的“观点”和“预测”仍然不能当事实；页面会分别标成观点/推测。

## 保留的最小对象

- 1 个事件：通宇通讯 002792。
- 2 份核心文档：对外投资公告、市场传闻澄清公告。
- 10 条展示 claim：3 条核心事实、1 条官方观点、1 条官方预测、2 条传闻、2 条官方否认；另展示 1 条市场反应。
- 5 个关键节点：08-05 公告、08-07 传闻、08-07 否认、08-08 市场反应、09-22 签署协议。
- 3 条通知：P0 官方否认、P1 市场异动、P1 签署新阶段。

完整数据仍在 `fixtures/tongyu/precomputed.json`（底层 17 条 claim），但核心页只展示一条事件线的代表 claim 和完整版功能。

## 不包含

- 事件收件箱 / 多事件列表；
- 简报视图；
- 版本 diff 弹窗（状态变化通过四个演化节点直接看）；
- 证据包导出；
- 合并审核；
- 行情/财务影响；
- 登录、权限、写接口（除后端已有的通知已读/reset，不在核心页暴露）。

## 演示状态

- 关注状态、当前同步步骤、事件关注状态存 `localStorage`；刷新页面会恢复。
- 底部“重新开始演示”会清除状态，回到首次关注页。
- 页面不再提供规则演练链接，也没有 `?scenario=` 入口；所有变化通过“同步最新”进入。

## 后端引擎

纯函数引擎已经落在 `apps/api/app/engine.py`：`match_event` 负责同一事件/同一 Storyline/相关的判定，`apply_document` 负责 update / rumor / denial / correction / conflict，`expire_event` 负责显式截止日过期。测试在 `apps/api/tests/test_engine.py`，说明见 [docs/engine.md](docs/engine.md)，当前 **32 passed**。

GitHub Pages 版本是客户端状态机演示，按同一套规则推进 v1–v5；它不连接实时后端。本地 FastAPI 仍保留真实引擎和 scenario API，供后续接 connector。

## 实现

- 实际页面：`apps/web/dist/core-simple.html`；`/core.html` 会自动跳转到它。
- 页面是单页客户端演示：首次关注、处理进度、同步更新、通知、事件抽屉和关注状态都由 JS/localStorage 驱动；quote、数字、链接来自同一份 `fixtures/tongyu/precomputed.json` 和 CNINFO 原文。
- GitHub Pages 不运行 FastAPI；本地动态版和 API 仍可在 `apps/api` 启动，接入真实 connector 后走同一状态机。

如果重新执行 `npm run build`，Vite 会清空 `dist`；把 `core-simple.html` 和负责跳转的 `core.html` 放到 `apps/web/public/`，即可随构建保留。
