> 只保留“公告 → 传闻 → 官方否认”这一条线。没有收件箱、简报、导出、合并审核、行情影响。

## 这条链路只做三件事

1. **看当前结论**：收购已确认；英伟达合作/2000 亿市场传闻已否认。
2. **一屏看完整演化**：08-05 公告 → 08-07 传闻 → 08-07 否认 → 08-08 市场反应，四个节点同屏，不需要点日期切换。
3. **用 A/B/C/D 判断证据**：每个节点只给等级 + 一句理由，不再用 94/35 这种难以解释的分数。

版式顺序：当前结论 → 四个时间口径 → 四个演化节点（P0 通知并入“否认”节点）→ 结论变化 → 底部折叠的“判断口径”。

页面顶部先给“最关键的三件事”：真的（3亿元/25%/不并表）、被否认/容易误读（英伟达合作/2000亿市场/开源生态不等于合作）、需要重新评估（澄清前两次三日涨超20%）；演化表之后是“还需要核对”（估值、25%经营影响力、传闻原始来源）。

## 证据等级

| 等级 | 含义 | 怎么用 |
| --- | --- | --- |
| A | 官方原文 | 交易所/公司公告，可直接作为事实 |
| B | 有原文的转述 | 正规媒体引用官方，需核对原文 |
| C | 无原文转述 | 网络传闻/匿名消息，只能当线索 |
| D | 已否认/撤回 | 不作为事实，保留在版本记录里 |

本页的判断逻辑只有三条：**来源是不是官方、有没有原文、有没有独立佐证**。不再展示六根柱状图。

注意：A/B/C/D 是**来源等级**，不是主张类型。A 级来源里的“观点”和“预测”仍然不能当事实；页面会分别标成观点/推测。

## 保留的最小对象

- 1 个事件：通宇通讯 002792。
- 2 份核心文档：对外投资公告、市场传闻澄清公告。
- 10 条展示 claim：3 条核心事实、1 条官方观点、1 条官方预测、2 条传闻、2 条官方否认；另展示 1 条市场反应。
- 4 个关键节点：08-05 公告、08-07 传闻、08-07 否认、08-08 市场反应。
- 1 条 P0 通知：官方否认。

完整数据仍在 `fixtures/tongyu/precomputed.json`，但核心页不展示市场异动、其他 claim 和完整版功能。

## 不包含

- 事件收件箱 / 多事件列表；
- 简报视图；
- 版本 diff 弹窗（状态变化通过四个演化节点直接看）；
- 证据包导出；
- 合并审核；
- 行情/财务影响；
- 登录、权限、写接口（除后端已有的通知已读/reset，不在核心页暴露）。

## 规则验证场景

默认页面不变；以下 URL 只在测试时切换场景，页面顶部会明确标注“演示场景（模拟数据）”：

- `?scenario=correction`：对价由 3 亿元更正为 2.8 亿元；旧值保留，新增 v5，P0 更正通知。
- `?scenario=core-denial`：核心收购被官方否认；原公告保留，事件状态变为 denied，P0。
- `?scenario=conflict`：两份官方材料对关键金额给出不同值；标记 disputed，不自动选边，P0。
- `?scenario=expiry`：交割截止日已过且未见完成；标为过期/未完成，不写成“假”，P1。
- `?scenario=new-stage`：签署股份转让协议；同一 Storyline 下新建 linked Event，不合并原 Event，P1。

这些场景用于验证规则和固定布局；其中 correction/core-denial/expiry 是模拟公告，new-stage 使用真实的 2026-09-22 签署协议公告。

## 后端引擎

纯函数引擎已经落在 `apps/api/app/engine.py`：`match_event` 负责同一事件/同一 Storyline/相关的判定，`apply_document` 负责 update / rumor / denial / correction，`expire_event` 负责显式截止日过期。测试在 `apps/api/tests/test_engine.py`，说明见 [docs/engine.md](docs/engine.md)。

四个场景页现在通过 `GET /api/events/{id}/scenario/{name}` 调用引擎；结论、版本号、P0/P1 和通知内容来自引擎返回，不再是页面手写模拟。默认页仍是静态基准。

## 实现

- 实际页面：`apps/web/dist/core-simple.html`；`/core.html` 会自动跳转到它。
- 页面是静态证据简报：所有 quote、数字、链接来自同一份 `fixtures/tongyu/precomputed.json` 和 CNINFO 原文；不需要 JS 交互。
- 无前端构建、无新数据库、无新服务；由现有 FastAPI 静态托管。

如果重新执行 `npm run build`，Vite 会清空 `dist`；把 `core-simple.html` 和负责跳转的 `core.html` 放到 `apps/web/public/`，即可随构建保留。
